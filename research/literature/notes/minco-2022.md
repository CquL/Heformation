- 作者：Zhepei Wang, Xin Zhou, Chao Xu, Fei Gao
- 年份：2022
- 发表：IEEE Transactions on Robotics（arXiv:2103.00190）
- 链接：https://arxiv.org/abs/2103.00190
- 本地 PDF：`papers/formation/minco-2022.pdf`（19,522,474 B，sha256 `4c7687d048338411…`）

- 与项目的对应：Swarm-Formation 的 README 明确其优化器建立在 GCOPTER/MINCO 之上；即本项目所用规划器的轨迹表示来源。

## 1. 它解决什么问题

- Problem：多旋翼轨迹规划在几何约束与动力学约束下如何兼顾解质量、效率与约束保真度。
- Inputs：用户定义的动力学约束、几何构型约束（安全走廊等）。
- Outputs：一条满足约束的最优/可行多项式轨迹。
- Assumptions：平滑映射可把几何约束**精确消去**；稠密约束评估与稀疏参数化解耦。

## 2. 它的任务、资源、通信和运动模型

- Task：无任务层。
- Agent / capability：单机（多旋翼），无能力差异。
- Resource：无。
- Communication：无。
- Motion：基于无约束控制努力最小化的最优性条件构造轨迹表示；线性复杂度时空形变；
  通过 flatness 映射反向微分支持状态输入约束。
- Execution feedback：无。

## 3. 对我们哪个接口或约束有影响

1. **"规划轨迹安全"与"实际动力学安全"的差距在这篇里是明确的**：本文只保证**多项式轨迹**满足约束，
   不含跟踪误差。这与我们 `d_ref` 与 `d_actual` 分开评价、以及 FaSTrack 的 `e_budget` 是同一件事，
   可以作为"为什么不能只检查参考"的又一处依据。
2. **约束是"精确消去"而非"惩罚"**：几何约束通过平滑映射消去，意味着**走廊/边界一旦声明就不会被软性违反**；
   而队形相似度是**代价项**（可被牺牲）。这解释了两者在失败时表现不同：
   障碍净距失败 = 约束被违反（严重），队形误差变大 = 代价被权衡（可接受）。
   → 我们的报告应据此区分"约束违反"与"代价变差"，不要把两者都记成同一类失败。
3. **它不提供任何任务语义**：再次确认运动后端不能承担任务完成判定。

## 4. 它要求我们增加什么实验或反例

- **反例：`test_reference_violation_and_actual_violation_are_reported_separately`**：
  构造一条参考轨迹贴边但实际偏离的运行，断言 `d_ref` 与 `d_actual` 分别报告，
  且**不得**把参考约束满足当作实际安全。
- **报告口径实验**：一次运行中同时出现"队形误差超阈值"（代价变差）与"障碍净距不足"（约束违反），
  断言两者在结果里是不同类别，不能混为一个 `FAIL`。
