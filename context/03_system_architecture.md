# 当前阶段架构：受限v9与固定七机AIR联合闭环

**2026-09-17：按用户冻结方案实施，详细接口与验收见[plan.md](../plan.md)。这是本项目集成，不是某一篇论文已验证的现成全栈。**

## 1. 总体链路

```text
Agent + Task + target_ref + TravelTimeProvider
                 ↓
Calvo v9 restricted-domain Python port
                 ↓ 唯一权威 Plan.items
ROS1 FormationAction → 一次 Swarm 组级目标
                 ↓
Swarm 固定七机 AIR → PositionCommand
                 ↓
qn RBF/PD、执行器与6DOF → 七台实际 Odometry
                 ↓ 连续到位/速度/新鲜度判定
Action Result → DelayEvent → planRepair → 更新 Plan
```

`wait_time = 0`；本版只修复已有协作关系上的时间，不做v13剩余任务重新分配。电池不形成约束，充电、fragmentation、relay与动态联盟人数关闭。实际状态由qn唯一推进，Action适配器不发PositionCommand。

## 3. 第一版的“联合”必须能被观察到

至少运行一个案例：某条路线绕行或等待，导致任务实际耗时变化；变化返回上层后，任务时间、队列或执行者确实被修复。没有这种反馈，只是几个程序接通，不足以叫联合协调。

D-ITAGS原本有可行性/旅行时间交错查询。Calvo原本有估计与延迟修复。对于只有目标订阅的局部规划器，不能虚构它提供完整提前代价评估；可先保留原调度估计和实际反馈，再决定是否增加必要查询适配。

第一版保留完整架构，不等于首版要联合优化全部通信路由、模式切换与连续轨迹的全局最优解。

## 4. 已冻结的在线上层

本阶段使用Calvo v9 restricted-domain Python port，原始MATLAB保留但不作为本轮运行依赖。任务派发通过本项目FormationAction，不要求先接入Calvo原生行为树执行框架。D-ITAGS及其他候选只作为后续对照，不能与当前调度器同时控制任务。

## 5. 运动后端不串联

Swarm、Primitive、RMADER和AMSwarmX最初在不同实验运行；不得让它们依次重写同一轨迹。CAT-ORA是符合假设时可单独调用的重排动作，不代替全部运动规划。

同一任务内换后端不是免费能力。只有任务边界、时间、初始状态、控制输入和切换行为对齐后才开放，否则先固定该次实验后端。

## 6. 母船与本地执行的边界

母船统筹任务与资源，各节点执行并报告。分布式规划器保留自己的原生邻机轨迹交换，母船不接管它的全部高频计算。执行者收到什么才知道什么；日志和RViz显示不成为额外控制通道。

每个平台只有一个动力学实例推进实际状态。上游原仿真可用作独立复现；集成时避免原模拟器和新平台仿真同时驱动同一agent。
