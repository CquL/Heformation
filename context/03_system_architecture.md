# 第一版架构：完整联合协调，原生接口与最薄适配

**本页是拟实施组合，不是某一篇论文已经验证的现成全栈。**

## 1. 总体链路

```text
结构化任务 + 可用平台/资源 + 已知地图
                       ↓
             母船侧联合规划协调器
    ┌────────────────────────────────────┐
    │ 任务分配、资源与时间安排            │
    │        ↕                           │
    │ 运动可行性、旅行时间或执行延迟      │
    │        ↕                           │
    │ 保留、修复或重新安排                │
    └────────────────┬───────────────────┘
                     ↓ 原生每平台任务队列/Action
             原生任务执行器 / 行为树
                     ↓ 最薄的动作映射
                按任务选择运动后端
        ┌────────────┼──────────────┐
        │            │              │
      UAV转场      按需编队       海面/水下
     Primitive等   Swarm等       平台对应后端
        └────────────┼──────────────┘
                     ↓ 原生参考或控制接口
              本地控制器与动力学
                     ↓ 状态、实际耗时、任务结果
                母船反馈与修复

跨平台：保留原生通信，可接受限网络测试。
本机：本机状态驱动本地控制，不绕母船网络。
```

## 2. 各块来自哪里

| 功能 | V2依据 | 必须保留的范围 |
|---|---|---|
| 分配—调度—运动反馈 | D-ITAGS [R08] | 原模型与运动查询，不自动具有所有电池/海洋约束 |
| 资源约束与执行监控 | Calvo规划及执行框架 [R09,R10] | 原模型不含一般任务前置关系；低层动作只是简化示例 |
| UAV一般多机导航 | Primitive [R03] | 原生基元与多机轨迹交换，不是严格编队或UUV模型 |
| 编队运动 | Swarm [R01,R02] | 原版/后续论文代码覆盖分开记录 |
| 开阔区重排 | CAT-ORA [R05]，按需 | 不当成带任意障碍的通用导航 |
| 海洋模型/仿真 | Fossen、Stonefish [R17,R18] | 需要实际接入和平台验证 |
| 网络联合仿真 | DANCERS、ROS-NetSim [R15,R16] | 基础设施不提供完整规划控制算法 |

[R01–R18见来源表](13_references.md)。引用某块不表示其与其他块的组合已经由原作者验证。

## 3. 第一版的“联合”必须能被观察到

至少运行一个案例：某条路线绕行或等待，导致任务实际耗时变化；变化返回上层后，任务时间、队列或执行者确实被修复。没有这种反馈，只是几个程序接通，不足以叫联合协调。

D-ITAGS原本有可行性/旅行时间交错查询。Calvo原本有估计与延迟修复。对于只有目标订阅的局部规划器，不能虚构它提供完整提前代价评估；可先保留原调度估计和实际反馈，再决定是否增加必要查询适配。

第一版保留完整架构，不等于首版要联合优化全部通信路由、模式切换与连续轨迹的全局最优解。

## 4. 只选一个在线上层

Calvo与D-ITAGS分别小复现。选择与第一版任务要求匹配的一个主求解器；另一个作为对照或后续替换。

若选择D-ITAGS但需要借用Calvo的行为树执行器，二者之间没有本次已验证的现成连接，必须映射任务和结果语义。不能把Calvo的原生Action当作D-ITAGS的既有接口。

## 5. 运动后端不串联

Swarm、Primitive、RMADER和AMSwarmX最初在不同实验运行；不得让它们依次重写同一轨迹。CAT-ORA是符合假设时可单独调用的重排动作，不代替全部运动规划。

同一任务内换后端不是免费能力。只有任务边界、时间、初始状态、控制输入和切换行为对齐后才开放，否则先固定该次实验后端。

## 6. 母船与本地执行的边界

母船统筹任务与资源，各节点执行并报告。分布式规划器保留自己的原生邻机轨迹交换，母船不接管它的全部高频计算。执行者收到什么才知道什么；日志和RViz显示不成为额外控制通道。

每个平台只有一个动力学实例推进实际状态。上游原仿真可用作独立复现；集成时避免原模拟器和新平台仿真同时驱动同一agent。
