# 当前阶段验收与长期近海场景

**2026-09-17：本轮验收使用[plan.md](../plan.md)的固定七机AIR方案，下方近海异构内容为长期场景背景，不是本轮全部必做项。**

本轮分层验收：Test B使用可自由排序任务验证受限v9选择、能力匹配、固定联盟、时间与repair；Test A验证七机Action实际驻留与异常；Test C验证MRTA→Swarm/qn→实际完成→DelayEvent→repair→后续Plan的完整链。

执行链使用A区、B区和返回起点三个独立execution_id；固定A→B→Return只说明闭环，不声称前置关系优化。当前单一固定联盟的`wait_time = 0`，真实小/大正延迟均传播到后续任务；不人为插入等待，正等待吸收及多逻辑执行单元资源竞争另行验收。

七台实际Odometry同时满足位置、速度、新鲜度并连续驻留才成功。planning/finish只是名义结束，过期里程计不得累计驻留。完整通过条件与结果文件以plan.md及02/15为准。

## 1. 长期近海场景描述

母船接收一组已知位置和工作要求的近海作业任务，系统根据平台资格、资源和时间条件选择执行者。航行器完成目标转场、区段跟随、区域路线或平台可行的定域作业，必要子团队在指定阶段执行编队。执行中出现绕行、延迟、任务追加、平台退出或消息异常，上层据此修复时序或重新分配。

任务对象来自外部，不模拟珊瑚/风机缺陷识别。整个场景检验控制侧作业组织，不宣称业务检测精度。

## 2. 后续异构实例需冻结的内容

一张已知地图、一组可执行作业位置/区段、平台清单及模型、资源与时间条件、选定上层和运动后端、可重复事件。任务数量应足以使有限平台之间产生真实分配和等待选择。

后续多执行单元场景不默认绑定全部执行者。当前固定七机允许验证任务排序与时间闭环，但不能据此证明任意成员分配、动态联盟或真实资源竞争。

任意前置关系是否纳入优化，取决于上层选型。Calvo原例不能靠额外等待逻辑冒充一般任务图联合优化；若要求这些关系，应测试D-ITAGS对应模型。

## 3. 只使用实际支持的作业动作

目标转场、区段跟随、区域路线、返回和按需编队都要映射到已经复现的原生动作。不会悬停的平台用其支持的定域或路径动作；没有编队规模变化接口的后端，不直接接受任意人数联盟。

长期项目以不少于5个参与作业的航行器和所需工作域为目标；当前阶段已经冻结7台AIR平台。后续异构组成另定，不能把当前AIR联调报为空水潜验证。

## 4. 四类最小测试

| 测试 | 问题 | 需要观察到的行为 |
|---|---|---|
| 正常任务 | 系统是否完整？ | 任务请求→分配→节点执行→结果回传 |
| 绕行/等待 | 是否真的联合协调？ | 下层不可行/耗时变化导致上层调整，而不是只输出提示 |
| 平台退出/追加任务 | 原生修复是否适用？ | 剩余工作重新安排或明确不可完成，不隐藏失败 |
| 延迟/短时断链 | 信息条件影响什么？ | 节点仅按已收消息行动，报告任务和安全退化 |

先单个事件解释清楚，再组合多个事件。不提前向算法泄露故障脚本，不把失联直接当平台物理退出。

## 5. 最少但完整的评价

统计任务完成与超期、总作业时间、资源使用、实际最小间距、实际跟踪/编队误差、规划和修复计算时间、消息延迟或失联条件。编队误差只针对启用编队的任务区间。

记录原生日志/bag、任务结果和必要状态/轨迹即可；无需为了评测建立另一套运行消息。计划轨迹不等于实际运动，计算wall-clock时间不等于仿真作业时间。

项目截图中的2 m/0.5°是最终目标，统计口径需明确。尚无姿态动力学时写“未验证/不适用”，不能填零。安全过滤后偏离任务目标不能算任务完成；也不能为通过测试无依据放慢轨迹、关闭碰撞或只截成功片段。

## 6. 对照要按研究层次

先确认原上游例子，再固定场景与信息条件比较上层或运动后端。不要同时改变任务、通信和动力学后把差异全部归于一个算法。

某方法原本不处理失联，其失联失败可以揭示边界，但不是唯一竞争基线；通信研究还应对照RMADER/DMPC-Swarm等专门工作。DANCERS等用于仿真支撑，不作为同类型规划算法比较。

一个场景应有不同起点、任务配置与事件实例，不能只留下一个固定成功剧本。正式数量和参数在原例复现后按实验预算冻结，不在资料阶段虚构统计结果。
