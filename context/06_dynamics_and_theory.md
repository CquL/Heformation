# 动力学与理论：先保留上游条件，再研究新增问题

**本页不规定一个预先成立的“统一控制理论”，也不要求先完成全套证明才允许原始复现。**

## 1. 复现与集成分别需要什么

原始复现时，先使用作者提供的模型、求解器、控制器和信息假设，不同时替换它们。记录该例子到底是轨迹规划、点模型闭环还是实体/动力学实验，不混用指标。

集成时，对变更点建立简短对照：输入目标是否改变、原运动限制是否仍成立、实际命令送到哪一级、本机/邻机信息是否满足原假设、仿真是否有第二个状态源。只检查实际变更引入的义务，不先建立统一Certificate消息系统。

## 2. 统一接口不等于统一动力学

UAV规划后端的速度/加速度限制和轨迹参数化，不会自动提供UUV的可执行性。Fossen/Stonefish提供海洋模型与仿真来源，但本次尚未验证与上层和UAV后端的组合。[R17,R18](13_references.md)

平台是否能停止、侧移、倒退、定点保持、入水或出水，必须按对应模型和原生控制能力判断。同一AAV在不同模式仍是同一实体与同一份资源；模式切换没有验证时先固定模式，不制造“改标签即跨介质”的成功结果。

## 3. 上游保证不能被扩大

| 成果 | 需要保持的条件/证明对象 | 不应扩大为 |
|---|---|---|
| D-ITAGS [R08] | 任务分配、调度、运动模型下的算法与解质量性质 | 任意平台控制稳定性 |
| Calvo [R09] | 原资格、电池、任务拆分/接替模型与修复规则 | 任意前置关系及通信路由联合最优 |
| CAT-ORA [R05] | 原文受约束的编队重排问题及无其他障碍等假设 | 任意复杂障碍、任意异构动力学的全局最优 |
| RMADER [R12] | 最大消息时延、已提交安全轨迹等 | 永久或任意断联安全 |
| DMPC-Swarm [R13] | 同步通信/计算、初始可行轨迹、实际—名义跟踪界等 | 未建模强扰动与欠驱动平台仍安全 |
| H-LTL/GCS [R11] | 论文限定任务、空间表示与兼容条件下的正确性/完备性 | 未知海洋环境中的无条件保证 |

以上按V2核查记录转述。准备实际采用定理时，必须回到所选版本正文逐项核对，不能仅引用此表代替证明。

## 4. 新理论从实际问题开始

先保存一个可重复失败：比如上层时序在避让后失效、部分节点仍执行旧任务、某类平台无法实现名义避让。然后回答：

- 是实现错误、接口映射错误，还是原模型确实没覆盖？
- 原文是否已经给出解决方法，只是当前没有按其条件使用？
- 在最合适的已有专门方法上，问题是否仍然存在？
- 新增哪一个变量、约束或更新规则才能解决，代价是什么？

修好一个接线错误不是新理论；把原论文没承诺的工况测失败也不足以单独证明创新。

## 5. 确有研究问题后再写数学模型

保留所选原论文的符号和目标，逐项列明新增输入、决策变量、约束及求解改动，不先规定所有子系统都用同一种参数化。

旧方案的任务/信息双图、执行误差界和安全信息时限可以作为候选工具，但不要求都实现。任务依赖、通信图、安全交互和编队图含义不同；同处一个优化问题不等于邻接矩阵相加，也不是自动创新。

若研究信息陈旧与运动能力，需先有可信状态预测/误差界，再讨论其怎样限制执行或通信；有限实验最大误差只是经验信息，不能直接成为确定性上界。基础三角不等式不单独写作首创贡献。

## 6. 证明与实验的最小交付

一项研究至少交代：问题和原方法差异、假设、算法、要保证的性质、证明适用范围、反例、对照与失败结果。分配/调度可行性、轨迹安全、实际跟踪、任务接续分别证明，不用一个“稳定”笼统代替。

数值求解成功不等于约束全部成立；有限采样无碰撞不等于连续时间安全；局部求解失败不等于数学无解；多个ACK也不自动构成任意不可靠网络中的原子切换。

当前新算法与组合理论均未完成。读懂原方法和做最小复现可立即推进，不等待为整个架构构造巨大的形式化系统。
