# 状态与通信：沿用原生机制，测试真正的信息可用性

**本页保留长期通信实验原则。2026-09-17当前阶段先按[plan.md](../plan.md)完成ROS1七机AIR实际执行延迟闭环；执行延迟不等同通信时延，本轮不宣称已验证受限网络。**

## 1. 本机状态可以从仿真器来

```text
本机控制器 → 本机命令 → 本机动力学积分
      ↑                     ↓
      └──── 本机状态接口 ────┘
```

本项目不研发定位，可以声明理想本机状态反馈，或使用明确误差模型的反馈。关键是状态来自实际积分结果，不是把期望轨迹当实际位置。

本机闭环不经母船网络；实际设备未来通过状态估计接口提供相同语义，不要求当前指定业务传感器。

## 2. 邻机信息通过原生消息获得

```text
j的本机状态/已发布轨迹
    → j原生发布
    → 网络传递
    → i原生接收
    → i按该框架规则使用
```

不必重造邻机消息系统。Swarm与Primitive本来就有里程计及轨迹广播/接收。V2核查记录包含相应源码位置。[R01,R03](13_references.md)

收到轨迹只表明收到了对方某次运动意图，不表示对方零误差跟踪，也不表示后来改变的轨迹已经同步。

## 3. 分布式程序不是海上网络模型

ROS节点互传消息，不等于物理可达性、传播时延、容量、丢包、队列或多跳已经建模。第一版保留原生收发，只在边界加受控网络条件，先不强制一套新的通用Transport类或协议标准。

控制侧首批消息为：任务下发、邻机状态/轨迹、完成/失败、能源和故障。大图像、声呐缓存不是第一版负载。所有测试涉及的远程通道都必须真正受条件约束，不能只延迟一个状态话题，而让任务/轨迹悄悄直达。

## 4. 最小实验层次

正常原生通信作为基线；之后依次测试有界延迟、抖动/丢失、指定短时断链。具体参数是实验配置，不虚称设备实测。

消息内容尽量不改；记录必要的源/接收时刻、丢失和任务结果以解释失败即可，不为了采集日志扩大运行协议。使用共同仿真时间，wall-clock计算时间另记。

若需要物理位置与网络双向影响，再评估DANCERS；ROS-NetSim提供同类方法依据。版本和连接器须实际验证，不把默认UAV/Wi-Fi示例叫水声模型。[R15,R16](13_references.md)

## 5. 不能绕过的边界

本机可见自己的状态；邻机和母船远程状态只能按收到消息更新。评测器可读全局真值用于算间距和误差，但不得将其反馈给算法。静态已知地图可以预装，未来故障脚本不能提前告知调度器。

Primitive的大规模共享内存仿真在原文中的用途要如实记录。测试受限通信时，不能保留一个共享内存真值旁路，再声称网络约束被检验。[R03](13_references.md#r03)

失联不等于实体消失；不得从碰撞集合中随意删除失联航行器。本地可继续什么或怎样退出应与采用框架的假设和平台能力一致。水下欠驱动平台不一定可以照搬四旋翼悬停策略。

## 6. 后续通信实验范围

固定可达边、固定网关可以作为仿真假设。移动中继/会合是否成为变量，先由资源与执行实验说明必要性。AAV能跨介质运动不自动等于具备RF—声学转发硬件。

RMADER是有界延迟下轨迹更新对照；DMPC-Swarm有特定同步通信/计算、丢包恢复与跟踪界条件；不能把二者安全模块随意串接后继承所有保证。[R12,R13](13_references.md)

本阶段不承诺任意长期断联也安全且完成全部任务。既要报告成功，也要定位假设失效时的方法边界。
