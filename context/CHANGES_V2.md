# V1 → V2.0：变更及全量替换说明

**2026-09-15｜适用对象：此前“项目背景与AI协作目录v1.0”资料包。**

## 1. 为什么不能只增加一份补丁

旧AGENT、盘点提示词、现状、架构、接口、计划和交接都包含“先审计并复用旧HUC”的要求。只放入一份新方案，AI仍可能按旧入口执行。因此，本次重写三个主体及其互相引用的内容，旧决定不再保留为可执行备选。

## 2. 主要变化

| 旧要求 | 新要求 |
|---|---|
| 先审计旧HUC，再沿用其模块 | 不读取、不审计、不继承旧HUC；只处理新工作区和选定上游 |
| 以旧Coordinator、Envelope、Sxx为框架基础 | 上游原生规划/执行接口为基础，差异处最少适配 |
| 第一版联合能力以后再补 | 第一版保留完整联合协调闭环；先独立复现是实施步骤 |
| Swarm作为唯一指定运动方案 | 保留已复现编队基线，优先新增Primitive，按动作选择后端 |
| 一开始冻结大量新数据包 | 先用Task/Action、Odometry、原生目标、轨迹和反馈 |
| 固定沿用旧ROS 2外壳及OR-Tools实现 | 原始复现使用上游环境和求解器，最终部署环境未冻结 |
| 先把三条融合点定成创新 | 作为研究候选，先有问题复现与近邻对照，再决定新算法 |
| 通信路由、缓存、信息截止时间全部先实现 | 第一版先测试原生控制消息的延迟、丢失和断链 |
| HUC本地版本与qn旧验证是必查项 | 从当前待办删除；海洋平台模型独立选型与验证 |

## 3. 文件级调整

`AGENT.md`整体改写；`AGENTS.md`只引导正文。`context/01`至`15`保留主题和大部分文件名便于替换，但内容全部以V2重组。

`prompt/01_repo_audit.md`保留为**停用提示**，只说明旧工作流失效并指向`01_upstream_selection.md`，不会再触发旧HUC盘点。其他常用提示词均更新为新上游复现、原生接口集成、实验和问题驱动研究。

旧`context/archive/`不进入新包。V2实施方案、核查记录和接续说明转入`context/sources/`原样保存；保留两张用户提供的报告指标截图。不收录旧输入接口截图为新规范。

记录模板从旧的多份必读要求收缩为三种可选短记录。没有新增运行时协议、强制数据库或日志平台。

## 4. 替换方式

本包是完整资料替换版，**不要只合并覆盖而遗留旧活动文档**。

对纯V1包：在新工作区外备份旧`AGENT.md`、`AGENTS.md`、`PROJECT_CONTEXT.md`、`prompt/`、`context/`和旧校验清单，再放入V2对应内容。该操作仅针对资料包，不涉及源码、未提交代码、实验结果或上游仓库。

对混合目录：先保留用户自写材料与其他项目规则，只替换V1包管理的文件；将冲突旧方案移出默认读取范围。若还有更高层的项目AI指令要求审计旧HUC，也要按用户本次决定一并纠正，但不得擅自覆盖无关规则。

完成后用新会话或明确的新任务重读AGENT.md。检查旧盘点提示词是否已变为停用页，最新交接是否指向上游复现，而不是旧P0/W01。

## 5. 本次整理的证据边界

本次读取了本地V1包、V2两份文档及其接续说明，按用户的新决定重新组织；没有访问旧HUC，也没有重新拉取其他GitHub仓库、安装上游、运行机器人测试或提交代码。

论文能力与开源状态沿用V2核查记录的时间与限定语。来源原文保留，未知项不改成已确认。资料校验清单只用于比对文件内容。
