## 2. 已实现并有代码或实跑证据

### 三机执行与 Action

三机在线注册：

```text
aav_1         -> drone_0
aav_2         -> drone_1
aav_3         -> drone_2
aav_formation -> drone_0, drone_1, drone_2
```

已经完成：

- 单机 member target 不叠加 formation slot；
- 三机组级目标使用 formation centre + slot；
- 目标话题按成员隔离；
- readiness 按成员检查，不再要求所有规划器订阅所有目标话题；
- 三机使用 `DECLARED_FORMATION`，期望图节点数为 3；
- 单机后切回组级时 `member_goal_active_` 会复位；
- Action 探针序列“单机 AAV2 → 三机组级 → 再单机 AAV1”已得到：
  - 路由 PASS；
  - 落点 PASS；
  - SUCCEEDED + Result PASS；
  - Result 可用于释放下一项 PASS；
  - 探针退出码 0。

三机编队启用证据是“3 节点期望图已构造且 similarity cost 路径被进入”，不是代价值大小。

### 任务模型与规划语义

已经实现：

- `monitoring_request_coastal.yaml`；
- 缺失必须字段时报错，不静默给 service time / deadline；
- 兴趣点按可覆盖集合展开，不按“一个兴趣点一个航点”机械展开；
- 单机任务默认不允许被更大的编队单元抢走；
- Executor 静态成员可重叠，但计划禁止共享物理成员同时占用；
- `build_executor_plan(..., serial=True)`；
- 串行起点使用：
  `max(F_serial, 本执行单元成员预计可用时间)`；
- 无在线端点的平台可保留在规划模型中，但不参与在线串行时钟；
- 成员预测位置按**物理成员**维护；
- 前序单机任务改变成员位置后，后续三机集结代价使用更新后的成员预测位置。
