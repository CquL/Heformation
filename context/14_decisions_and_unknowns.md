## 3.1 本轮新增的实现级决定（2026-09-18）

| 决定 | 依据与适用范围 |
|---|---|
| qn 12ODE 的第三行符号约定按原模型保留，不改动力学 | 实测：标准机身速度按严格 `R(q)*v_body` 旋转后与兼容话题差 1.7–2.4 m/s，而按模型自己的映射差 0.0 m/s；改它等于改动力学，plan.md 禁止 |
| 兼容话题的世界系线速度以“发布位姿的数值导数”为准 | 100 Hz 梯形差分与兼容速度的 99 分位差 0.004–0.005 m/s，说明规划器反馈的是真实世界系速度 |
| 采样台账按监测节拍（20 Hz）记账，越界判定按整段新鲜窗口 | 窗口内任一样本越界即重置驻留；台账只负责缺失/对齐统计，不替代窗口判定 |
| 参考采用证据由 runner 建立，不由 Action server 自证 | execution_id 由 runner 保存并映射到 Action GoalID；组级目标只由授权发布者发一次 |
| `UNKNOWN_LOCKED` 的恢复必须是整链重启 | 只清 Action 锁会把旧轨迹服务器和旧 qn 状态留在运行中 |

## 3.2 P3 离线执行单元层（2026-09-18）

| 决定 | 依据与适用范围 |
|---|---|
| 执行单元只作为离线计划层模型，不拆分当前七机物理编队 | plan.md 明确本阶段只验证资源选择与计划层竞争；ROS 任务链仍走固定七机联盟 |
| 资格由能力与人数决定，代价在合格单元之间决定 | 复用已移植的 v9 奖励序；唯一推广是每个单元各自维护队列完成时间 |
| 执行单元的成员集合固定，不重排、不共享 | 同一物理单元不能同时属于两个执行单元；计划校验会拒绝这种定义 |
| 该层不复制完成/修复语义 | `process_completion`/`plan_repair` 仍是固定联盟语义，避免出现第二套 repair 实现 |
| 平局按 `executor_id` 打破 | 选择结果不依赖调用方给的单元/任务顺序 |

本阶段范围和接口已冻结，按[plan.md](../plan.md)实施并以实验确认行为。长期未知包括多执行单元的合法等待/资源竞争场景、海面/水下模型与平台组成、真实通信设备参数、最终误差统计口径及研究增量；这些不阻塞当前七机AIR闭环。
