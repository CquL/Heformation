# 决策与未知：V2以后不恢复旧工作流

## 1. 已明确的项目决定

| 决定 | 状态 |
|---|---|
| 不再读取、审计、参考或继承旧HUC | 用户此次明确要求，替代旧P0及复用决定 |
| 先复现有价值的上游成果，再原生接口最小集成 | 用户明确方向 |
| 第一版保持母船联合协调器与节点执行完整闭环 | 用户明确方向，不降为只有单独编队演示 |
| 不做业务识别、载荷选型或定位算法研发 | 用户明确范围 |
| 协同不等于全体始终同步编队 | 用户明确语义 |
| Swarm是已确认复现基础，不必锁为唯一最终后端 | 用户确认起点与此次调整 |
| 先测问题，再确定原创模型、算法和证明 | 用户明确研究路线 |

## 2. V2建议，尚待实际冻结

| 事项 | V2默认建议/候选 | 尚待决定 |
|---|---|---|
| 新运动基线 | 优先复现Primitive-Planner | 在具体场景是否选其在线导航 |
| 唯一在线上层 | Calvo资源优先；D-ITAGS任务依赖优先 | 小例结果与首场景约束决定 |
| 原生执行器 | Calvo配套行为树可参考/复用 | 与选定求解器、运动后端的实际映射 |
| 编队附加功能 | 保留Swarm；CAT-ORA按需 | 第一版是否需要开阔区重排 |
| 网络测试 | 先原生消息+受控条件，再评估DANCERS | 实际连接器、时钟、模型与版本 |
| 海洋模型 | Fossen/Stonefish为候选来源 | 采用的具体平台模型与控制接口 |
| 运行环境 | 原始例子隔离，不同时迁移 | 最终ROS/系统部署尚未冻结 |

候选不是安装清单，更不是已完成的组件。不能因已写在AGENT中就把它当作用户最终选型。

## 3. 必须遗忘的旧执行决定

“先盘点旧HUC才能开始”“沿旧Sxx/Envelope扩展”“强制旧ROS 2外壳/OR-Tools”“先搭统一证书与大消息包”“三条融合机制已经是新理论”均不再适用。

这些话只用于标识撤销项，不是保留一条可回退的默认工作流。本包的旧`01_repo_audit.md`名称只保留停用提示。

## 4. 当前少量未知

选定上游的本地运行路径、版本、许可证与依赖；第一任务场景的具体资源/关系需求；五节点工作域组成；海面/水下控制模型；真实通信设备参数；报告误差的最终统计口径；候选方法相对最近邻的增量。

能从所选上游和新工作区解决的先读取；真正缺失且影响当前动作时集中确认。不再把旧HUC版本、旧qn链路等列为阻塞新工程的必查项。

## 5. 决策更新

一次选型用简短文字记录日期、依据、选择、未采用理由及适用范围即可。新增决定同步到当前状态和交接；不要修改来源原文、保留两个都叫“当前主方案”的版本，或将未实际运行的方案写成复现事实。
