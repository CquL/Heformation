# 项目背景与研究边界

**更新：2026-09-19**

## 1. 项目定位

本项目研究海上异构无人集群如何：

- 把高层作业请求转化为可执行任务；
- 根据平台能力与资源选择执行者；
- 组织单机、编队、中继、会合等协同角色；
- 把运动可行性、实际执行结果和信息到达反馈给任务层；
- 在延迟、故障、资源占用和后续通信约束下修复或重新安排任务。

母船是上层任务与资源协调中心，各平台保留本地运动规划、控制和状态闭环。

最终目标平台固定为：

```text
3 × AAV
1 × USV
1 × UUV
```

## 2. 协同不是所有平台始终编队

协同可以是：

- 多平台并行执行不同任务；
- AAV 子队在某一阶段保持编队；
- USV 为 UUV 提供通信或定位支援；
- 某个平台等待另一平台的数据到达；
- 任务接替、补测和重新安排。

编队只是协同中的一种运动模式。

## 3. 当前第一版

第一版当前冻结为**近岸监测 AAV 子系统验证**：

- 三台 AAV 在线执行；
- 支持单机巡查与三机岸线编队观测；
- 高层请求经任务展开和 Executor 选择后派发；
- 监测完成依据实际 qn 状态、有效观测和结果接收，而不是只看是否到达航点；
- 必要时最多释放一次条件复测；
- USV/UUV 保留在目标资源模型中，但没有在线执行端点。

七机 Swarm/qn 配置继续用于 M2 与回归，不代表最终平台组成。

## 4. 当前不做

不研发：

- 珊瑚白化、风机缺陷等业务识别；
- 业务传感器选型；
- SLAM 与定位算法；
- 高保真相机/声呐感知；
- 尚无依据的大一统消息协议；
- 未经实验验证的“全局新控制理论”。

观测质量当前是声明式工程代理，与真实装备能力分开记录。

## 5. 长期目标功能

后续逐步加入：

```text
USV 水面执行
UUV 水下执行
真实或受控通信窗口
USV 中继 / 数据汇聚 / 会合
能量约束
任务—通信—运动联合安排
AAV 水中及跨介质模式
```

这些属于目标架构，不是当前完成事实。

## 6. 研究方法

先构造可重复系统和反例，再判断已有方法是否已经解决问题；只有剩余缺口稳定、可形式化并能通过实验或理论证明时，才形成自己的研究方法。

当前“Task–Information–Motion coupling”“通信 deadline 由任务/动力学反推”“联合中继角色选择”均是候选研究方向，不是已证明创新。
