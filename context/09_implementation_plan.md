# 当前实施计划：V2六步，不回到旧HUC盘点

## 1. 目标先固定，实现按可运行单元推进

第一版就是完整母船联合规划协调器与节点执行系统。独立复现和单链联调是实现步骤，不是取消上层、先只做编队。第一版也不要求已经具有任务/运动/通信/模式联合全局最优或全系统安全定理。

## 2. 六步计划

| 步骤 | 工作 | 必须留下的实际交付 |
|---|---|---|
| 1 原始复现 | 保留Swarm；复现Primitive、Calvo和D-ITAGS的清楚小例子 | 原文/代码对应、命令、配置、结果或具体失败原因 |
| 2 冻结上层 | 根据能源/长时工作或一般任务依赖需求，选一个在线主求解器 | 明确选型理由，未选者只做对照 |
| 3 原生接口组合 | 复用执行器，连接一个运动后端，只补必要动作/结果映射 | 一次任务从请求到完成的实际闭环 |
| 4 联合反馈 | 使用提前运动查询或实际延迟，让下层变化影响上层 | 一个绕行/等待导致时序、队列或执行者改变的可复现实例 |
| 5 异构与通信 | 接经验证的海洋平台分支，注入受限通信，按需评估仿真连接器 | 如实列出实际通过的模型/域/链路条件与失败 |
| 6 问题与新方法 | 比较最合适既有方法，冻结一个有价值的真实缺口 | 新模型/算法差异、对照和证明义务 |

不以所有候选工具都安装完为步骤3前提。首轮多个小复现可隔离推进；不能把多个在线调度器合并控制同一任务。

## 3. 当前最小待办

已有Swarm作为基线保留。下一次从[上游选型与原例定位](../prompt/01_upstream_selection.md)开始，确定本次一个目标；V2优先新增Primitive的官方导航例子，上层以Calvo资源小例和D-ITAGS任务依赖小例支持选型。

未获得本地证据时不填具体commit、日志和运行命令结果。所需环境能从选定上游读取就先读取；没有许可或访问失败要具体说明，不能改成从头设计新求解器。

## 4. 阶段边界

原始复现运行原模型；当前Swarm已在Docker Noetic中完成原始编译并在平台边界替换为qn AIR闭环；连接阶段不同时迁移操作系统和其他算法；实验阶段不绕过消息限制；研究阶段不提前规定一定要改Swarm或一定研究信息年龄。

海洋平台模型可以从一开始并行做独立核对，但对应控制链未通过前不作全域验收。图像识别和未知传感器不是任何步骤的必需前置任务。

## 5. 不再存在的前置工作

旧方案P0/W01的“读取旧HUC、盘点Sxx、复用Envelope/现有调度器”全部撤销。当前没有审计旧HUC后才能工作的门槛，也不把旧ROS 2外壳或OR-Tools作为必须继承的环境。

## 6. 排期与记录

按原例是否可运行和接口是否闭合推进，不在未知依赖与许可下承诺固定几天。一次工作结束用一段交接说明当前版本、实际结果、阻塞和唯一下一步即可；有必要再用[简短实验记录](templates/experiment_report.md)。

步骤1中的Swarm + qn AIR运动基线已经通过；Primitive、Calvo和D-ITAGS仍待复现，步骤2至6尚未完成。最新实际状态见[02](02_current_status.md)、[15](15_handoff.md)。
