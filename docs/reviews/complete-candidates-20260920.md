# 完整候选计划阶段记录

现有调度器新增显式完整候选入口，默认Calvo路径不变。业务Task保留作业要求，ExecutionCandidate/ExecutionStep记录某候选的完整执行方法，选择后进入ExecutorPlanItem。它们是内部计划数据，不是新运行节点或后端工厂。

已验证：

- 完整工期比较避免“先做最便宜一步导致总工期更长”的反例。
- 后继查询获得更新后的物理成员位置/模式。
- 未使用的晚可用资源或执行方式不阻塞其他任务。
- 预算耗尽保留已找到的完整候选，未知模式不冒充最优性证据。
- 合成成本反例中，计入转换/返回改变AAV与UUV的选择；该项是调度逻辑测试，不是动力学对照实验。
- 原生PVS查询已生成完整候选计划：正常场景UUV总时长约62.43s，终点在减速尾段之后。该自动生成PlanItem经现有runner真实派发并完成，证据在`experiments/20260920-mode-candidates/runner-r1/`。

在尾段障碍场景尝试的直行及目标后转向候选均被原生模型判定冲突，失败保留，没有因此放宽净距或更换控制参数。未找到候选不是数学无解证明。
