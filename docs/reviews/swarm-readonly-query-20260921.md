# Swarm只读查询与当前回归结果

本轮补充AIR联合规划所需的原生只读运动查询。上游源码快照不修改，通过`swarm_readonly_query.patch`在镜像中接入；实验镜像为`swarm-formation-qn:swarm-query`，尚未作为已验收默认镜像。

## 已实现

独立可执行程序直接调用原PolyTrajOptimizer的A*初始化及L-BFGS优化，读取原规划参数、显式声明的完整静态地图及邻机参考。私有GridMap初始化不注册ROS发布、订阅或定时器。程序不会创建Goal/轨迹发布器，Python调用方负责共享单调截止时刻、超时终止和结果读取。

输出是名义参考的时长、系数、速度及编队配置，不是qn实际跟踪或整项任务成功。地图输入是已声明静态场景，不冒充在线局部感知的完备观测；邻机静止是显式输入假设，也支持已有多项式参考。未来时刻的动态邻机查询尚需明确评价时间绑定。

原代码两处边界同时修正并供在线/查询共用：A*无路径时不能继续索引路径首元素；两点路径按两段初始化时插入已计算的中点，避免访问不存在的第三个点。保留原优化权重、迭代参数与图机制。

## 查询证据

`experiments/20260921-swarm-query/run-r1`：

- 2米短路径：FEASIBLE，查询约1.09秒，名义参考7.01秒。
- 障碍路径：FEASIBLE，查询约1.12秒，名义参考23.22秒；最大高度1.635米，起终点0.8米。声明静态机体几何检查未发现违规。
- 障碍内部目标：INFEASIBLE。
- 三台实际规划器的Goal/trajectory新增消息均为0。

这里的FEASIBLE表示原优化器接受了名义地图参考；例如短路径最大速度0.535m/s高于原优化参数0.35m/s，该参数在原代码中进入软代价，不能据其字段名声称得到严格速度上界。实际平台限制仍须单独核查。

## 回归未全部通过

七机`seven-r1`原生Action成功，但位姿/速度尾部检查失败。异常样本ROS间隔约5–8ms或14–19ms，实际模型积分仍为10ms；按模型步长复核残差约2.4e-5m/s。旧镜像`seven-control`也出现同类失败，因此不能归因为新查询接口或坐标变换。增加被动GC暂停诊断后，新镜像`seven-r2`按原判据PASS；没有改GC策略、模型积分、时间戳或验收门槛，尚未证明此前抖动的唯一原因。

**三机`three-r1`仍为失败。** 三个观测及集结成功，编队转场实际净距0.404m低于0.50m，Action非成功并保持UNKNOWN_LOCKED。不能以只读路径合格或七机一次通过掩盖这次真实失败。需继续对齐该段实际参考、邻机轨迹和qn状态，确定是参考裕量、跟踪、时序还是初始化变化引起。

新查询尚未接到完整AIR候选与观测/交付模型，AAV跨介质查询预算、完整请求、实际状态/信息边界、返回/复查、UI及科研对照仍未完成。当前只读查询不是最终五平台交付。

## 参考时间修正后的实际复验

`experiments/20260921-reference-time/three-r1`在相同原请求、1.5m/s和0.50m实际表面净距门槛下，五项原生Action均SUCCEEDED，六点几何观测／交付完成，资源释放。编队转场实际最小净距0.735091m，使用中参考最小净距0.865337m；修正前分别为0.404249m和0.468701m。修正传递原FSM已经采用的未来轨迹开始时间到原优化器，不改图权重、目标、安全下限或qn控制器。

这是单次同配置复验，不能据此证明时间错位是所有失败的唯一原因，更不能认定任意状态安全。此次最大参考跟踪误差仍为1.318901m，不能用0.3m经验跟踪裕量当严格界。既有采样安全／采用／时间判据在此次动作通过；本例无实体障碍，不替代港口编队验收。七机兼容复验正在进行。

此前Docker build-r2解包报错保留；重新核对时镜像可直接启动，容器源码及产物包含最终时间修正，无需凭旧错误日志清理缓存或重复重建。对照见`transfer-comparison.json`。

七机`reference-time/seven-r1`原生Result成功但一项兼容有限差分尾部失败，GC二代暂停17.54ms与异常时段对应；`seven-r2`试验冻结启动GC图后无长暂停，却有七项p99失败。已撤回该GC策略，保留被动诊断及全部失败。不能将三机修复通过写成七机兼容通过。采样时间抖动仍未解决。
