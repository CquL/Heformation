# 三机并发轨迹更新的安全合同修正

## 已定位的问题

`qn-runtime/three-r1`失败时，新0轨迹11与旧1轨迹31、新1轨迹32与旧0轨迹10分别安全，只有新11+新32的组合参考净距0.466987m<0.50m。原生系数复算与pos_cmd重建差<2e-7m；约0.3秒后实际净距0.441643m。故不能归因于显示、模型优化数值或更大的跟踪误差。

同一实际镜像源码显示：优化最终只检查地图；peer更新硬门以0.6667m中心距检查、周期门只有约0.5333m；而既定几何要求为0.25+0.25+0.50=1m中心距。未来循环还反复使用固定当前时刻的位置。来源是原Swarm源码、已发布多项式和既有物理合同，不新增编队控制算法。

## 最小改动

新增补丁`swarm_peer_safety_contract.patch`，不修改upstream快照。保留优化软权重及swarm_clearance语义，仅为三机启用从原半径/净距派生的1m硬中心距；七机默认0关闭，保留原分支。原优化终点、实际提交时刻、新peer更新与周期未来检查均使用同一绝对时刻。退休轨迹、WAIT_TARGET、参考暂停及安全保持仍不能被普通规划重启。

新peer后的复核复用原SWARM_CHECK→REPLAN_TRAJ，不新增协调节点或原子提交协议。终点按原traj_server保持、未来起点不负时间外推；更早地图障碍不能被晚到的peer预警遮蔽。

## 验证

- 18项原生多项式确定性断言通过，原新新反例在约+11.202s提前检出，其余三个新旧组合不误报；包括实际提交时刻偏移、终点保持、负时间与退休历史。
- 补丁应用、三机/七机参数展开、traj_opt和ego_planner_node编译通过。类布局新增字段后额外重编swarm_readonly_query，避免旧查询二进制ABI不一致。
- 第一次实验镜像启动因继承bash入口退出126，未启动ROS或Goal，记录保留；改为显式env入口。
- `experiments/20260921-peer-safety/three-r2`在原1.5m/s和0.50m实际净距门槛下五项原生Action均SUCCEEDED，几何交付1.0、资源释放。转场实际最小净距1.091589m，使用中参考最小净距1.127432m，实际参考采用确认通过；日志出现SWARM_CHECK触发重规划。
- 七机代表回归`peer-safety/seven-r1`原185项全部PASS；重编只读查询以新硬合同在约1.02秒内成功，前后ROS发布/订阅/服务图一致。当前实验镜像`swarm-formation-qn:peer-safety`尚未替代默认镜像。

证据：`experiments/20260921-formation-review/`的原始对照、源码、编译/断言/参数展开；`experiments/20260921-peer-safety/`的实际运行。

## 边界
