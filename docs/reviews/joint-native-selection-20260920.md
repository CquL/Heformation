# 原生观测与支援方法：有限选择进入正式执行

本轮第一次由既有build_executor_plan选择水下观测/支援方法，再交给现有runner实际执行。范围是一个UUV/USV协作业务，**不是完整三类平台请求或五平台总验收**。

## 已连接的路径

TravelTimeProvider接收有限完整方法，每个方法复用既有Executor、NativeActionSpec和PlanItem：

1. 同一模型快照下查询各参与者完整运动、尾段与有界终端等待。
2. 使用共同几何检查路径；对参与者的采样净距，以及较早完成者之后的原生空闲运动进行校核。
3. 用同一本地观测与FiniteDelivery规则检查是否观测到要求的样点、是否能在已检查的承诺区间内接收产品。
4. 不可行方法剔除；可行方法作为多个活动交给原搜索，按方法完成时间比较，分别更新成员终态/可用时间。
5. 所选步骤经正式runner预装载、支援启动确认、作业启动、产品接收与原生Result校验后释放。

仍只使用原生PVS和现有搜索，没有新在线求解器、协调节点或控制器。AAV没有已合格的完整联合查询时仍是UNKNOWN，不能套用水面/水下模型或距离除速度。

## 预算失败与修正

桌面Python对六个方法规划约7.17秒，但第一轮Noetic容器`run-r1`超过10秒，在发送Goal前报PlanningBudgetExceeded。失败保留；没有延长预算。

不同等待方案反复计算同一段运动是其中一个开销。PVS查询现在可以从已经确认的终端状态继续积分；完整源模型、路径、推力、场景、积分步长、终端条件和模型期限都参与指纹检查。匹配时复用轨迹前段，继续原控制器、执行器和动力学；不匹配拒绝续算。等待增量仍逐步检查速度、介质和几何，不改步长、不冻结姿态、不跳过积分。

检查证明续算与完整重算的整段轨迹及结束时间相同，改变推力的旧缓存被拒绝。缓存只存在于该次固定快照调用内；内部指纹、模型和密集路径不复制进步骤/Goal。

## 尚未证明的部分

- 这六个方法来自实验脚本的有限声明，尚未从完整请求自动生成全部观测视点/通过段、转换入口与支援位置；水下样点只有一个，不代表一般覆盖联合优化已完成。
- 搜索完成只针对这六个名义方法，不是连续路径或全平台全局最优性。
- 规划使用声明初始模型快照，真实端点接纳前还执行当前状态的原生预检；尚未完成运行中权威模型快照/通信返回给调度器的闭环。
- 名义通知身份及产生时刻用于预测编码长度，实际传输按实际编码长度计费；尚未绑定完整计划实际Goal身份，也未完成跨多个协作业务的全局共享容量检查。
- 参与者之间的名义几何校核不替代所有五平台的完整在线冲突处理及独立实际安全审计。
- AAV完整查询的10秒预算、Swarm只读查询、正式联合请求UI确认、跨介质/复查/返回、科研对照继续保留未完成。
