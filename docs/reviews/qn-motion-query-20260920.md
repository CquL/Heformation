# AAV状态副本运动查询：当前结果与预算缺口

本增量服务于三类平台协同计划第二步：让AAV跨介质方法像PVS方法一样，从实际模型快照计算完整运动及终端条件，不能用距离/速度替代转换与稳定时间。当前是查询边界实现，尚不是完整业务请求或在线资格放开。

## 实现

在现有`QnPythonClosedLoopBackend`增加`snapshot()`和`predict_native_fragment()`，现有`ExecutorTravelTimeProvider.execution_candidates()`直接调用。没有新增ROS接口、控制节点、后端工厂或另一个模型。传入模型保留完整控制器、执行器、Memory和水平导引状态；查询deepcopy后用原`step()`与原0.001秒内步、0.01秒外步积分，不reset源模型。完整内部副本只用于预测后继，密集轨迹和模型不复制进Goal/步骤元数据。

查询使用现有Segment位置参考，与在线LocalPlatformAction共用`segment_terminal_ready()`的物理条件；在线仍额外检查参考采用与时间有效性。每段包括运动后稳定和原4秒保持，转换保持原垂直入口边界。非原生已配置LOS分支、未检查等待状态或非垂直转换返回UNKNOWN。几何使用共同静态场景，并检查子积分点；结果是给定快照下的采样可行性，不是严格安全包络或新增模式资格证明。

顺便修正了既有有限候选枚举的执行次序：迭代器栈先深入一条候选链取得完整解，再查询兄弟方法。之前先生成整层替代方法，可能没有完整解就被某个慢查询耗尽预算。保留同一有限搜索与同一单调截止时刻，不新增求解器；两任务、第二执行单元查询阻塞的反例验证完整先前方案仍被保留。

## 实测

证据目录：`experiments/20260920-qn-motion-query/`。

输入采用已有垂直入水14秒、短WATER参考7秒、出水14秒片段，另包含每段实际稳定/保持，不将35秒参考时长冒充完整工期。

| 运行 | 结果 |
|---|---|
| 原Python、在线10秒预算 | 10.00185秒返回UNKNOWN，已积分35.43秒模型时间，源模型未变 |
| 离线完整参考计算（观察上限60秒） | 16.08167秒完成54.85秒模型运动，终态AIR；这是离线对照，未更改在线预算 |
| 实验性同源Cython编译、10秒 | 仍UNKNOWN，约41.38秒模型时间；不足以用于本次完整在线候选 |
| 实验性编译、离线完整对照 | 13.36146秒，5485个轨迹样本及全部终态控制器/执行器数据与原Python完全相同（仅此案例），源模型未变 |

首次Cython类型推断编译失败，生成的嵌套ctuple类型未定义；无类型推断和混合配置可构建，但均未满足在线预算。**不将Cython纳入生产依赖或默认运行链**，实验只证明此尝试不足。不能将单例数值相等推广为全部状态下的等价证明。

查询/候选/转换处置相关17项检查通过。新增检查覆盖非固定编号drone_2的原生模型候选、源模型不变、终端保持、预算UNKNOWN和模型数据不进入Goal元数据；未展开参数穷举。

## 尚需继续

完整AAV跨介质查询仍超出10秒在线预算，未用更大在线预算、粗积分或欧氏代价掩盖。仍需解决查询开销，以及运行时同版本实际状态快照、Swarm只读运动查询、有限观测候选/支援/交付的联合决策。原生资格端点继续保持experimental/qualification_only边界。

本轮来源是现有qn/PVS源码与已声明片段合同；交错运动查询、有限预算和完整可行方案保留依据仍见`docs/requirements/cooperation-source-design-20260920.md`。本轮没有新增文献或控制理论。

## 2026-09-21：同方程Python热点优化

当前Noetic完整片段对照见`experiments/20260921-qn-hotpath/comparison.json`。减少RK4重复状态包装、float转换及生成器，复用同一步已算出的AIR输出与RBF衰减因子；精确零门控不删除积分器连续状态。未改变控制方程、物理模型、1ms内步、10ms外步或终态条件。

本次同容器基线19.459309s，优化14.759010s（降低24.15%）；与早期16.08s测量不可混为同次负载对照。5476外步轨迹及全部终态字段相同，54760内步状态／执行器／两类Memory／命令二进制摘要一致，源模型未变。仍需10.001071s返回预算UNKNOWN，不能据性能改善宣称满足10秒或全任务候选搜索完成。

共享实现的预声明七机1.5m/s回归`experiments/20260921-qn-runtime/seven-r1`通过原185项检查；保留此前采样失败。最慢循环分阶段诊断表明此轮backend与发布占主要计算/等待开销，锁等待为微秒级；单次通过不能推导任意宿主负载下的实时性。三机完整原请求复验正在执行。

三机复验`qn-runtime/three-r1`前四动作成功、转场实际净距0.441643m而失败并锁定。尽管同一控制器代表片段逐状态等价，在线Swarm/参考生成受运行时序影响，不能把等价性证明扩展为这次在线运动相同。七机通过与三机失败分别记录；编队实际可靠性仍未通过。

## 同源编译的受控实验（尚非生产依赖）

`experiments/20260921-qn-compiled/`固定Noetic CPython3.8.10、Cython3.2.9（仅实验目录构建工具），使用同一两模块源码，禁用fast-math和FMA contraction。仅一次base和一次预声明typed配置：纯Python14.0833s，base完整9.8576s但独立10秒预算仍UNKNOWN；typed完整9.4072s，独立10秒预算9.6985s完成54.76模型秒，冷进程总9.7581s（不含Docker启动/构建）。

typed与纯Python的5476外步轨迹、54760内步全状态与命令摘要、全部终态字段完全一致，预算内成功结果亦一致，源模型未变。这支持后续受控接入同源编译查询，不能证明任意场景/宿主负载稳定满足10秒；剩余0.3015s也不够宣称Swarm、完整计划校核和多候选搜索总预算通过。生产Dockerfile、运行依赖和在线预算均未因此改变。
