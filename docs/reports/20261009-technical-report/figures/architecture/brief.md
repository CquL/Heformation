# 图1：统一任务与运动反馈闭环

## 内容与位置

替换第1.1节的原六蓝框架构图。内容沿用用户已确认的A/B/C共用任务链和报告统一模型；本轮是图形表达修订，不引入新框架、控制律或实验证据。

## 组成

- 作业输入：A区域调查、B风机巡检、C平台／管路巡检，以及实际状态与平台能力。
- 本研究任务组织：统一模型表达成员、模式和作业；联合决策选择成员、方法和支援；完整Plan表达并行、接续、预计时序和必要前置。
- 复用执行端：用户确认后通过原Action派发；AIR使用Swarm＋qn，WATER使用qn，USV使用Otter/PVS。它们是原方法与本项目接线，不标成新控制理论。
- 实际反馈：合格区间、匹配终态及报告实收；触发后继或剩余作业调整。任务闭合后驻留，人工授权返回。Qt与独立RViz读取同一任务状态。

## 主线与回路

作业输入及实际状态进入统一模型，经联合决策形成完整可派发Plan，确认后派发平台执行。实际运动与事件回到计量及收件；合格作业、匹配终态和必要实收决定闭合，实际反馈独立回到联合决策更新剩余作业。实线表示主链和实际数据，虚线只表示反馈调整。

## 阅读重点

三种业务共享任务组织与反馈；不同平台保留原运动后端。预计方案不是实际完成证明，闭合由实际合格量及关联事件确认。

## 风格

参考FigGenie的control-loop与control-data：`asplos25-131_fig2`的独立边缘反馈、`asplos25-052_fig5`的共同组织与不同执行实例。白底、透明分区、灰色原后端、一处深蓝重点、细线与正交主路径。按报告14.65cm插入宽度设计，中文标签不靠缩小字号挤入。

## 解释边界

1. 深蓝强调联合决策，不宣称基础控制算法原创；来源为本报告第2、3章。
2. AIR／WATER是模式后端，不是两组互不相交的物理机器人；AAV可能跨域，同一成员占用保持唯一。
3. 实收是本报告对应历史任务级通信模型，不将此图说成逐跳物理通信实现。
4. 图中人工返回保留已确认语义，不新增跨任务切换验收。

## 图题与图注

图1 异构集群任务规划与协同执行闭环。三业务通过统一模型进入联合决策，确认后使用各平台原执行端。实际合格区间、匹配终态和必要实收用于任务闭合，并通过虚线回路调整剩余作业。
