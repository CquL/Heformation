# 各平台路径规划与四份报告材料核查

核查日期：2026-10-09。代码基线：`main@b5a59ceb`。核查对象是当前三业务主入口的源码、启动接线和用户新提供的四份材料；本次没有启动运动仿真。

## 1. 当前每个平台使用什么路径规划方法

当前链路包含任务联合决策、作业几何生成、局部路径选择、运动轨迹或短指令生成、模型跟踪和实际反馈几个环节。qn和Otter/PVS提供控制及动力学；具体路径算法须从其执行端追踪。

| 平台／阶段 | 路径与运动生成算法 | 跟踪／动力学 | 当前输入输出 |
|---|---|---|---|
| AAV1、AAV2、AAV3的AIR | 已知自由空间内的有界A*局部目标选择；Swarm原生A*初始化／已有轨迹初始化；五次多项式最小jerk轨迹及L-BFGS优化 | qn AIR控制和刚体／推进模型 | 实际位置、速度、局部地图、作业目标及邻机参考 → 短目标 → 连续位置／速度／加速度／yaw参考 → 实际Odometry |
| AAV的WATER | `LocalSurveyMap.next_target`有界A*及可通行直连短段；设施轮廓前视／沿线／残余区间引导；按声明速度递推短参考 | `LOS_VELOCITY_REFERENCE`及`LOS_SURGE_YAW`工程水下引导，qn WATER模型 | 实际位置、深度、观测地图、动态成员及当前作业段 → 水下短参考、主要沿路线的航向 → 实际运动及合格区间 |
| AAV的ENTER／EXIT | 在接纳的转换柱上，按实测自由空间逐段推进垂直参考，核对位置／姿态与介质交接 | 同一qn物理状态与控制交接 | 合法入口、转换柱、目标高度／深度、实际状态 → 入水／出水参考和实际介质终态 |
| UUV | 与AAV WATER共用局部A*、已知自由短段和巡视引导 | 当前专用WATER-only qn实例，使用qn水下动力学代理 | 水下实际状态、范围／设施作业及局部地图 → 短段路线与前进式控制；保持WATER |
| USV | 水面局部A*选择短目标；有限推力／指令时长候选，逐候选使用当前Otter状态预测短运动与零推力停稳尾段，选择首个可接纳指令 | LOS横向误差航向引导、Otter原生航向自动舵及PVS水动力／推进器模型 | 实际全状态、局部地图、邻机、服务／返航目标 → 短航向／推力指令 → 实际运动、到位与停稳状态 |
| 母船 | 当前作为声明位置的部署／接收端 | 当前场景没有接入母船自主航行控制 | 提供部署／返回参考和接收位置 |

三台AAV的算法和基础能力相同；角色由当前任务和状态决定。同一AAV的AIR和WATER属于同一个物理成员，转换时连续交接。

### 1.1 共用的局部导航

核心代码：[observation_coverage.py:83](../../integration/qn_aav_simulator/src/qn_aav_simulator/observation_coverage.py#L83)、[next_target:391](../../integration/qn_aav_simulator/src/qn_aav_simulator/observation_coverage.py#L391)。

- 地图更新以传感器首回波射线为依据：射线内部标记自由，命中标记占据，其余保持未知；另接入明确声明的部署自由空间先验和禁入政策。
- A*队列优先级为路径长度加目标距离；搜索限于已知自由体素，重复访问量用于近目标局部探索排序。
- 同一深度／高度层附近采用水平四邻域；存在垂向运动时可加入上下邻域。目标在未知或占据位置时选择当前可达、朝向目标的局部候选，不穿过未知单元。
- 优先尝试经完整包络检查的直连短段；存在障碍时搜索绕行。当前默认网格0.25m，单次搜索上限25ms／768个展开节点，返回的是当前安全短目标。这些是工程配置，不能当成论文规定常数或全局最优界。
- 环境包络、动态成员预测与相关采用前检查共同决定短段是否可接纳；边界不足时返回无可执行短目标，由原执行／反馈逻辑继续感知或保持。

`LocalSurveyMap`参考已知／自由／占据地图与frontier引导思路。FUEL／FALCON是方法背景，工程没有整套部署其多机探索算法。

### 1.2 AIR的Swarm轨迹优化

调用证据：[formation_action_server.py:1568](../../integration/qn_aav_simulator/scripts/formation_action_server.py#L1568)、[局部目标发送前导航:1874](../../integration/qn_aav_simulator/scripts/formation_action_server.py#L1874)。原生实现：[planner_manager.cpp:181](../../upstream/Swarm-Formation/src/planner/plan_manage/src/planner_manager.cpp#L181)、[poly_traj_optimizer.cpp:7](../../upstream/Swarm-Formation/src/planner/traj_opt/src/poly_traj_optimizer.cpp#L7)。

Swarm采用`MinJerkOpt`表示分段五次多项式，将中间位置与时间作为优化变量，用L-BFGS求解。目标函数同时包含平滑、时间、障碍、邻机、运动限制及按模式启用的编队图相似度项。其初始化可以使用原生A*，连续重规划也可以从上一已采用轨迹初始化。

单机AIR和组级返航共用原规划器。组级时启用编队关系，并在目标选择时检查各成员包络；不同任务角色使用相应单机目标。所用Swarm补丁还包含当前已提交邻机参考冲突检查及参考交接修正。

方法／源码来源为[Swarm-Formation官方仓库](https://github.com/ZJU-FAST-Lab/Swarm-Formation)及其ICRA 2022论文。报告应标明官方源码复用和工程改动，编队图指标的来源也属于原方法。

### 1.3 WATER的路径和控制

调用证据：[platform_action.py:145](../../integration/qn_aav_simulator/src/qn_aav_simulator/platform_action.py#L145)、[短目标:226](../../integration/qn_aav_simulator/src/qn_aav_simulator/platform_action.py#L226)、[参考递推:266](../../integration/qn_aav_simulator/src/qn_aav_simulator/platform_action.py#L266)。

WATER先选择当前短目标，再按声明速度推进位置参考并连续调整航向。普通扫描保持声明深度；设施巡视保留所选深度层及三维连接意图。主要运动是前进、转向和深度跟随。工程引导分支按照参考速度与位置追捕误差形成前进速度、航向意图，使用航向速率限制和原执行器能力实现跟踪。

UUV启动接线明确为`qn_aav_node.py`、`LOS_VELOCITY_REFERENCE`、`LOS_SURGE_YAW`，见[five_qualification.launch:43](../../integration/qn_aav_simulator/launch/five_qualification.launch#L43)。它与AAV共用水下执行逻辑，当前模型口径是qn水下代理；旧REMUS分支不用于当前UUV主链。

路径跟随的方法背景可参考[Fossen作者的LOS研究说明](https://www.fossen.biz/php/research/path_following.php)。报告需给出工程实际使用的引导方程和控制分配，不能只写一个文献名称代替当前实现。

### 1.4 USV的局部运动选择

调用证据：[pvs_node.py:178](../../integration/qn_aav_simulator/scripts/pvs_node.py#L178)、[短指令候选:261](../../integration/qn_aav_simulator/scripts/pvs_node.py#L261)、[pvs_backend.py:225](../../integration/qn_aav_simulator/src/qn_aav_simulator/pvs_backend.py#L225)、[预测检查:280](../../integration/qn_aav_simulator/src/qn_aav_simulator/pvs_backend.py#L280)。

USV水面A*给出几何短目标，执行端继续用Otter原模型判断指令可执行性。候选包括原声明推力／半推力、多个有限时长，以及有条件的无附加前进推力转向、短反向推力和coast。每个候选保留航向控制器、推进器迟滞和当前状态，检查计算期间的coast、短运动和停稳尾段；采用时还绑定模型时刻与全状态摘要。

这是工程有限指令搜索，借鉴“只接纳具有可停稳续段的动作”的思想。原[DWA作者说明](https://www.cs.cmu.edu/~dfox/abstracts/colli-ieee.abstract.html)是在速度空间搜索；当前实现搜索的是Otter可执行的有限指令，不应直接写成已经完整部署标准DWA或通用MPC。动力学与自动舵源码来自[PythonVehicleSimulator](https://github.com/cybergalactic/PythonVehicleSimulator)。

### 1.5 B/C作业几何与路线的关系

[inspection_work.py:82](../../integration/qn_aav_simulator/src/qn_aav_simulator/inspection_work.py#L82)提供三类共用作业意图：圆滑外轮廓分层巡视、偏置沿线运动、指定位置局部作业。几何意图由选定设施和范围生成。

执行端从实际状态选择到入口、段间连接和绕障短段。进度由实际合格区间并集和连续合格驻留计量。报告中应同时交代“作业范围怎样生成”和“平台怎样实际走到并完成作业”，两者均有具体代码依据。

上层B/C联合搜索位于[executors.py:3034](../../integration/mrta_python/executors.py#L3034)，输出成员／方法／接续／支援，默认10秒预算、首个完整任务级候选返回。它不为水下和USV生成Swarm多项式轨迹。

## 3. 对当前报告写作的直接影响

这四份材料支持两类输出：中期汇报PPT展示研究进展、指标、成果与经费；专题技术报告详细论述研究问题、数学模型、算法、理论推导和验证。先前中期执行情况报告的“二／1、不超过3项重要进展”要求仍适用于那份管理报告的指定小节，不能据此把完整技术报告限制成三个短条目。

初次核查时的2026-10-05理论稿是原中期执行报告指定小节的12页独立素材，包含统一模型和整体可行性推导；该旧稿现已按用户要求删除，当前入口为[2026-10-09专题技术报告](20261009-technical-report/README.md)。以下保留当时针对素材整编的核查要求：
