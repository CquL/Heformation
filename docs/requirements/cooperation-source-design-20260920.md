## 2. 用户需求、平台属性、决策变量必须分开

用户给出：作业区域/样点、要求的观测产品、接收方、完成与返回要求；模板已有作业规则可以直接加载，不要求用户逐个填写控制参数。

- AAV的AIR/WATER/转换能力由平台配置与资格记录提供，默认进入候选集，不要求每次勾选允许入水。
- 能力是机型属性；当前健康、介质、已占用成员与有效转换入口是运行可行性。不能把“机型两栖”误写为任意实际状态可转换。
- 业务有硬截止就输入；没有则无硬截止，目标仍可最小化完成时间。不能将任意900s当成必需任务要求，更不能让优化器自己选一个任意晚的deadline。
- 禁止某水域入水、禁用某载荷属于外部作业限制，才约束候选；不是默认操作步骤。
- 是否复查由已收到的初测结果和已有任务规则决定；用户可指定作业政策，不负责选择执行平台。
- 设备尺寸、有效链路模型、观测驻留要求必须来自模型/任务模板或明确实验假设，不逐个塞进Goal；没有依据的模糊/分辨率代理不恢复。

系统选择：任务由谁做、何时做、从哪个合格入口入水/出水、采用哪条候选路线、USV在哪里/何时支援、哪些动作并行、何时集结/编队/解散、收到结果后由谁复查、何时返回。

已有三台AAV的机型目标相同，但当前在线跨介质资格端点只在drone_0显式打开。后续必须用同一已验证代码/配置逐成员注册和核对，不能永久把AAV3写成“水下专员”，也不能未经验证直接扩大能力。

## 3. 一个代表性任务与三类协同关系

一次近岸分层观测请求：完成若干空中观测区域和若干水下样点，必要结果送达母船，根据收到的异常标志最多复查一次，执行规定终端/返回。

场景：共同静态障碍地图，选柱/墙/礁石盒等能被现有几何一致表达的障碍；水面、海底、允许转换区域来自同一配置。障碍要影响路线、入口或运动冲突，不只用作背景。VRX不进入必要依赖，当前试接保留作参考。

三种关系分别有实际用途：

1. **并行与资源竞争**（R1–R3）：AAV空中观测和UUV水下观测没有真实依赖时可并行；AAV选择跨介质后，其空中/编队容量减少，必须与其余任务一起比较。
2. **共同作业/支援重叠**（R5–R6）：USV与水下数据源在所选通信机会中共同占用；不是“USV动作结束→UUV开始上传”，也不是两者互相等结束。USV预定位不能依赖必须经其转发才收到的通知。
3. **结果前置与运动先后**（R4）：母船收到合格初测产品后才释放复查；狭窄共享空间按已检查的冲突顺序通过，实际清空/完成才释放。UUV若不能停在边界，就提前承诺可执行尾段/等待路线，而不是到边界才急停。

这三类关系都使用现有Plan中的任务、成员与先后关系。通信共同作业用已有计划项引用参与者及支援区间；不建立第二套协调节点或任务真相库。

不能永久规定AAV1/2做空中、AAV3做水下、UUV走剩下的点。应比较完整候选：

```
水下样点：UUV水下路线→观测→通信机会→终端/返回
      或 合格AAV空中路线→选定入口转换→水下路线→观测
         →交付/出水顺序→返回

交付：经USV转发
  或 有资格的平台出水/返回后直接交付（只有确有该链路与动作能力才枚举）
```

如果所有数据都能无代价直接送达，USV作为中继没有优化价值，应诚实报告它可以待命；不为展示硬派它走一段。代表实例采用明确的受限水下链路，使支援对完成产生作用；条件来源写实验假设，不伪装成装备实测指标。

## 4. 必要约束与证据边界

| 约束 | 对决策的影响 | 依据与验收反例 |
|---|---|---|
| 作业能力/实际介质/转换入口 | 无资格不能选，合格AIR/WATER方法参与竞争 | R2/R3/R10；仅改模式标签或接管服务成功，不得判实际入水完成 |
| 障碍、海底、禁入区、实际机体净距 | 剔除不可行路线，改变入口/平台/时序 | R7+几何原理；参考无碰撞但实际碰撞仍失败；Swarm不能替PVS自动避障 |
| 动力学、执行器与终端能力 | 转弯、转换、作业、尾段及等待均占空间/时间 | qn/PVS原控制和本地资格；通过样点后仍滑行，不能瞬间释放 |
| 物理成员互斥与原子预订 | 单机/编队/跨介质入口共享同一资源 | R1/R3；AAV编队占用全部成员，不得与其单机动作重叠 |
| 任务/运动前置与协作重叠 | 决定可并行部分和必要等待；新增先后边联合无环 | R4/R6；禁止把通信重叠写成双向完成依赖 |

| 信息因果、链路容量与接收 | 通知/数据分开计，母船收到才释放结果依赖 | R5/R6+守恒；断链不增接收量，中继不转发未收到的前缀 |
| 断联前承诺与异常 | 接纳证据齐备后才进入依赖支援的片段，失约有界处置 | R5的承诺会合思想+项目执行合同；USV拒绝时水下平台不得照常进入断联段 |
| 时间、状态可靠性、参考唯一 | 失效则故障/未知锁定；实际完成不被预测时间替代 | R4+现有Action；重发/旧Result不解锁，UI不能补造成功 |
| 业务截止/能量余量（有声明时） | 作为硬约束，不用人为权重交换安全与任务要求 | R1；无截止不人为填入；无可信功率模型时只报告当前假设，不称能耗最优 |

当前第一项任务不需要额外加入海浪谱、全套水声协议、图像识别、动态障碍预测或在线任意编队形状搜索。除非明确作业需求或现有反例要求，否则不增加字段。

## 5. 如何把任务分配、资源调度和Swarm实际连起来

采用现有完整候选入口，不引入新的在线求解器。有限候选不是全连续问题的精确解，候选生成器必须写明覆盖范围。

1. 从同一状态快照读取物理成员位置/模式/健康/占用、已收到结果和场景版本。
2. 展开未完成的业务要求；观察任务先不绑定机器人。只为实际需求生成依赖，不强迫UUV等待所有空中任务。
3. 按平台能力枚举有限方法：独立AIR、合格AAV跨介质、UUV水下、USV支援及已配置AAV编队；转换入口/通信位置从可达有限集合选，不让用户手填动作序列。
4. 对候选查询实际后端可行性与耗时。PVS复用已实现状态副本查询；AAV AIR使用原Swarm的运动结果/有依据的耗时模型；q​​n转换从当前资格配置取得，遇未知不能退回欧氏距离/统一速度。
5. 先检查硬约束，再比较完整计划完成时间。将USV支援和上传作为重叠区间，而不是把并行参与者耗时求和；同一AAV内部连续动作才按次序累计。
6. 搜索共用一个单调预算，保留完整可行候选；只有存在可证明的下界才能剪枝，不能把欧氏距离估计或某次成功当作普遍可行性保证。当前简单枚举容易在产生完整候选前花完预算，需要优先取得可行完整解，并缓存同版本状态的重复查询（R2）；不新增搜索引擎层。
7. runner提交时复核版本，按物理成员原子预订，使用选定端点派发；终态/实际安全与接收事件驱动后继。
8. 延迟先修复尚未开始部分；已接受本地片段和参考不覆盖，失败成员继续锁定，缺少通信只保留承诺不假定释放（R1/R3/R4/R5）。

默认主目标：最小化满足全部必做观测、必要接收以及规定终端/返回后的任务结束时刻。没有硬期限同样可优化；有期限则额外约束结束时刻。能耗是已声明可靠模型下的可行性/报告指标，不先拼任意加权和。

统一表示可写为：选择`z_j=(成员集合,方法,入口/路线,支援方案)`以及时序`s_j,f_j`，最小化`T_end`；`T_end`覆盖全部必需接收事件及规定返回。物理成员在所承诺片段/终端内只能属于一个执行承诺。数据在产生后才能传，每跳累计发送不超过该节点已接收量，并满足该链路实际区间容量。

这些是R1–R6机制在当前问题下的组合建模，不声称某篇论文已经解决了本系统，也不新建一个大而全协议。

## 6. 编队的实际位置与必要纠正

当前Swarm承担AIR分布式轨迹优化，qn承担实际跟踪，二者都保留；没有理由再加一个编队控制器。USV/UUV协作是任务、通信和空间关系，不加入AAV编队图。

上层决定：在哪个任务段采用既有三机编队、何时集结、成员是否全部实际可用、何时解散。下层沿现有路径执行，继续记录原生相似度和实际净距；不把编队优化器放进高层每个时间步同步求解。

对同一作业段，独立运动候选与编队候选都必须包含完整代价：成员各自到集结位置、最慢成员等待、集结安全、编队转场、解散后续状态。当前把巡查后无条件追加编队动作的实现仅是回归演示，不是联合决策。

**不能假装编队天然提高监测效率或降低能耗。** R8说明多机器人收益必须有任务模型，R7只证明其运动机制。若作业有明确同时观测/相对几何要求，编队是满足作业的候选方法；具体要求必须来自任务书/载荷合同。若没有这种需求或实测收益，优化器可能始终选独立动作，这是合理结果，不能用负代价、任意奖励或每次强制编队制造优势。

项目的编队能力验收可以在同一场景设一个明确标注的编队转场/收队工况，并与独立转场作对照；它是控制能力验收，不冒充未经证实的业务刚需。是否能在主业务任务中形成可发表的编队收益，是仍须验证的研究问题，不能由用户复选框替代，也不能从总交付中静默删除。

| `NativeSegmentSpec`→ROS `PlatformSegment`→后端`Segment` | 各保留计划、传输、执行所需语义，序列化只在runner边界做一次；参数与前置条件共用纯校验函数 | 每经过一层都复制全部模型/历史/诊断 |
| `_executor_goal`明确拒绝len(execution_steps)>1 | 在既有worker顺序执行选定步骤，按活动GoalID处理结果；同成员跨介质链内不中途释放，阶段失败停止后继 | 通用工作流引擎/新的生命周期管理器 |
| `Executor`与`ExecutionUnit`分别包含规划属性与端点绑定 | 静态成员/能力从同一配置加载，端点路由仅作薄转换，实际占用保留runner唯一权威 | 按后端再复制一套机器人状态与资源服务 |
| `observation_coverage.py::FiniteDelivery`已有守恒逻辑，在线runner仍用零延迟 | 复用计数模型接产生/接收事件，母船只从接收边界获得结果；日志文件不充当传输 | 数据产品注册中心、真实文件传输/水声协议栈 |
| `PlatformTaskAction`接纳即执行，断联许可尚未实现 | 在现有本地片段中落实有限协调确认后推进；所需信息只为此明确用途存在 | 通用事务协调器或行为树框架 |
| `bounded_travel_query`子进程负责硬预算隔离 | 保留确有阻塞风险的一个隔离边界，使用同一截止；避免对已在隔离中的纯查询再层层启动进程 | 通用RPC层、每个数值步骤一个服务 |
| VRX视图/Gazebo代理 | 保留实验入口但不作为主链依赖；当前图形与安全地图不一致，不能称完成场景接入 | 同时运行多个权威物理后端 |

“减少封装”不是删掉GoalID、成员互斥、坐标转换或参考采用检查。这些检查对应已经发生过的错误；真正应减的是重复状态、无消费者字段、同义包装和多处重复决策。

## 8. 理论与创新：把可以证明的结论和未证明的主张分开

研究问题仍是：**模式转换和交付可执行性如何改变异构任务分配与编队执行时序，并使执行反馈下的修复保持一致。** 不是给三个图统一起名。

- 事件/资源正确性：在统一成员身份、原子预订、按GoalID幂等、真实前驱/接收事件释放的条件下，证明不会重复占用或提前释放。属于系统不变式，单独不称算法创新。
- 进展：只有当联合先后关系无环、每个已接受动作和终端有界、承诺通信机会能实现且有足够容量时，才论证最终进展；故障时正确终止/锁定，不承诺永远成功。
- 运动安全：若经过证明的跟踪界为e_i、e_j，参考净距需计入r_i+r_j+d_safe+e_i+e_j；当前经验误差不能直接当作这些界。Swarm软代价和PVS离散采样均不构成连续时间安全定理。
- 解质量：只对有限候选与声明模型讨论。完整枚举且所有可行性确定时可与该候选集精确参考对账；预算未穷尽不能称最优。D-ITAGS的界不自动继承。
- 方法创新仍待验证：至少证明相对于同约束的串行/局部分配、忽略转换或忽略交付的方案，联合方法改变决策并改善实际任务完成；只有工程集成和新字段不够。

## 9. 后续实施顺序及出口

1. **输入与执行模型收敛**：取消默认人工入水/编队决策；无期限请求正常规划；统一steps来源。用确定性实例验证资格改变候选，预算UNKNOWN不当数学无解。
2. **时间与完整动作接线**：定位当前状态过期/模型时间问题，不放宽阈值；打通AAV/UUV完整候选与runner，含实际终端/返回。用障碍使某入口不可行，验证选择改变。
3. **同请求通信协作**：预承诺USV与水下平台片段；收到量控制真实后继。用通知不可达、USV拒绝、链路不足、重复接收作负例。
4. **编队方法纳入计划**：先比较同作业要求的独立/编队完整代价，再调用原Swarm执行；无证据不加虚构收益，保留明确控制能力验收。
5. **一项完整任务和少量对照**：同一次请求覆盖分配、实际跨介质、支援、有限交付、一次条件复查及规定返回；三类平台不是固定分工。五节点展示属于代表验收配置，不作为每次任务强制使用全部平台的规则。

必测：不输入deadline仍可优化；同一AAV多模式不被双占；相同需求下改变入口/支援代价会改变选择；不共享资源并行；通过式作业尾段仍占用；未接收不释放复查；USV会合不等待断联通知；重复/旧Result不解锁；缺时序/状态证据不通过。

这不是新一轮框架开发。运行结构继续是：**现有请求/调度/runner → 现有原生Action → Swarm/qn/PVS → 实际事件反馈**。可视化是旁路。研究完成后实施仍等待用户恢复暂停目标。
