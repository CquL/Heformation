## 2. 用户需求、平台属性、决策变量必须分开

用户给出：作业区域/样点、要求的观测产品、接收方、完成与返回要求；模板已有作业规则可以直接加载，不要求用户逐个填写控制参数。

- AAV的AIR/WATER/转换能力由平台配置与资格记录提供，默认进入候选集，不要求每次勾选允许入水。
- 能力是机型属性；当前健康、介质、已占用成员与有效转换入口是运行可行性。不能把“机型两栖”误写为任意实际状态可转换。
- 业务有硬截止就输入；没有则无硬截止，目标仍可最小化完成时间。不能将任意900s当成必需任务要求，更不能让优化器自己选一个任意晚的deadline。
- 禁止某水域入水、禁用某载荷属于外部作业限制，才约束候选；不是默认操作步骤。
- 是否复查由已收到的初测结果和已有任务规则决定；用户可指定作业政策，不负责选择执行平台。
- 设备尺寸、有效链路模型、观测驻留要求必须来自模型/任务模板或明确实验假设，不逐个塞进Goal；没有依据的模糊/分辨率代理不恢复。

系统选择：任务由谁做、何时做、从哪个合格入口入水/出水、采用哪条候选路线、USV在哪里/何时支援、哪些动作并行、何时集结/编队/解散、收到结果后由谁复查、何时返回。

三台AAV的机型目标相同；已存在同一qn的AIR/跨介质资格端点和Swarm往返证据，但请求候选生成还没有注册三台AAV的完整跨介质方法。必须复用同一实现并逐成员核对实际入口状态、介质和参考归属，不能永久把AAV3写成“水下专员”，也不能将某次资格成功扩写成任意状态下均可转换。

## 3. 一个代表性任务与三类协同关系

一次近岸分层观测请求：完成若干空中观测区域和若干水下样点，必要结果送达母船，根据收到的异常标志最多复查一次，执行规定终端/返回。

场景：共同静态障碍地图，选柱/墙/礁石盒等能被现有几何一致表达的障碍；水面、海底、允许转换区域来自同一配置。障碍要影响路线、入口或运动冲突，不只用作背景。VRX不进入必要依赖，当前试接保留作参考。

三种关系分别有实际用途：

1. **并行与资源竞争**（R1–R3）：AAV空中观测和UUV水下观测没有真实依赖时可并行；AAV选择跨介质后，其空中/编队容量减少，必须与其余任务一起比较。
2. **共同作业/支援重叠**（R5–R6）：USV与水下数据源在所选通信机会中共同占用；不是“USV动作结束→UUV开始上传”，也不是两者互相等结束。USV预定位不能依赖必须经其转发才收到的通知。
3. **结果前置与运动先后**（R4）：母船收到合格初测产品后才释放复查；狭窄共享空间按已检查的冲突顺序通过，实际清空/完成才释放。UUV若不能停在边界，就提前承诺可执行尾段/等待路线，而不是到边界才急停。

这三类关系都使用现有Plan中的任务、成员与先后关系。通信共同作业用已有计划项引用参与者及支援区间；不建立第二套协调节点或任务真相库。

不能永久规定AAV1/2做空中、AAV3做水下、UUV走剩下的点。应比较完整候选：

```
水下样点：UUV水下路线→观测→通信机会→终端/返回
      或 合格AAV空中路线→选定入口转换→水下路线→观测
         →交付/出水顺序→返回

交付：经USV转发
  或 有资格的平台出水/返回后直接交付（只有确有该链路与动作能力才枚举）
```

如果所有数据都能无代价直接送达，USV作为中继没有优化价值，应诚实报告它可以待命；不为展示硬派它走一段。代表实例采用明确的受限水下链路，使支援对完成产生作用；条件来源写实验假设，不伪装成装备实测指标。

## 5. 如何把任务分配、资源调度和Swarm实际连起来

采用现有完整候选入口，不引入新的在线求解器。有限候选不是全连续问题的精确解，候选生成器必须写明覆盖范围。

1. 从同一状态快照读取物理成员位置/模式/健康/占用、已收到结果和场景版本。
2. 展开未完成的业务要求；观察任务先不绑定机器人。只为实际需求生成依赖，不强迫UUV等待所有空中任务。
3. 按平台能力枚举有限方法：独立AIR、合格AAV跨介质、UUV水下、USV支援及已配置AAV编队；转换入口/通信位置从可达有限集合选，不让用户手填动作序列。
4. 对候选查询实际后端可行性与耗时。PVS复用已实现状态副本查询；AIR原Swarm只读查询已存在，但参考生成尚不等于qn完整跟踪可行。qn转换必须从当前资格和完整状态副本查询取得，遇未知不能退回欧氏距离/统一速度。
5. 先检查硬约束，再比较完整计划完成时间。将USV支援和上传作为重叠区间，而不是把并行参与者耗时求和；同一AAV内部连续动作才按次序累计。
6. 搜索共用一个单调预算，保留完整可行候选；只有存在可证明的下界才能剪枝，不能把欧氏距离估计或某次成功当作普遍可行性保证。现有逐项候选搜索已优先走完一条完整链，并在相同调用快照内复用查询；AAV首次完整查询仍可能耗尽预算，须降低实际查询成本而非跳过完整性校核（R2）；不新增搜索引擎层。
7. runner提交时复核版本，按物理成员原子预订，使用选定端点派发；终态/实际安全与接收事件驱动后继。
8. 延迟先修复尚未开始部分；已接受本地片段和参考不覆盖，失败成员继续锁定，缺少通信只保留承诺不假定释放（R1/R3/R4/R5）。

默认主目标：最小化满足全部必做观测、必要接收以及规定终端/返回后的任务结束时刻。没有硬期限同样可优化；有期限则额外约束结束时刻。能耗是已声明可靠模型下的可行性/报告指标，不先拼任意加权和。

### 5.1 统一问题的最小定义

下列是方法要求，**不是现有求解器已经完整执行的约束清单**。业务要求集合`Q`固定；有限方法`m`声明可覆盖的要求`C_m`、参与者、内部活动、合法入口/终态和接收/返回条件。方法选择`x_m`、各活动开始/结束`s_a,f_a`、冲突顺序、有限等待与通信机会一起决定计划。视点和通过段属于方法选择，不能先贪心固定再仅优化派谁执行。

目标统一为：

\[
\min T_{\rm end},\qquad
T_{\rm end}\geq\max\{f_q^{\rm work},\ r_p^{\rm mother},\ f_i^{\rm return}\}.
\]

其中只包含本请求必做作业、必要产品和规定返回；复查仅在接收规则激活后加入。不能用“最后一个移动结束”替代上述最大值。无业务截止时不添加期限；求解仍共用10秒预算，预算耗尽状态不等同于数学无解。

| 同一个可行计划必须满足 | 具体含义与底层理由 |
|---|---|
| 覆盖 `sum(x_m, q∈C_m) >= 1` | 每个必做要求都有合格方法；`C_m`必须经对应介质、实际/预测路径的范围、LOS与连续驻留确认。多个成员零碎驻留不能相加，不按平均覆盖率掩盖漏掉的必做样点。当前区域方法要求单个方法覆盖该区域全部样点；跨方法集合覆盖尚未实现。 |
| 能力与状态连续 | 选中的每个活动具有端点与资格；前活动终态必须为后活动合法初态，包含模式、位置及模型/控制器状态。AIR→WATER须经合格转换区和原生转换步骤，不能靠改标签获得。 |
| 动力学与完整代价 | 每段查询包含转场、转弯/转换、观测、必要等待、尾段及规定返回，各计一次。并行UUV作业与USV运动按各自时钟累计，再取有关完成时刻的最大值，不相加。 |
| 成员占用 | 同一成员的活动区间不得重叠；同成员复合承诺到规定终端前持续占用。不同参与者按各自活动区间预订，不能把整个联合方法的包围区间当成每个成员的占用。已接纳的未来会合亦为承诺。 |
| 活动前置与释放 | 完成前置要求`s_b >= f_a`，启动前置要求收到有效启动承诺后才释放作业；二者不能混成“支援必须先完成”。资源/运动/业务先后关系联合查环；要求共同作业的区间必须重叠且满足容量，不用双方互等完成表示。 |
| 全计划空间可行 | 所有同时存在的平台，含待命、转换、集结/解散、尾段和已承诺未来片段，均需校核实体/禁区/海底及成对净距。一个方法内部两条轨迹通过，不代表与别的并行方法无冲突。冲突改变路线/入口/顺序后须重算受影响时序。 |
| 编队方法 | 只有完整集结、最慢成员等待、Swarm编队段与解散终态一起合格才可选。三机物理成员互斥、下层原生约束与相似度项保留；没有载荷收益证据不加奖励，允许独立方法获选。 |
| 接收与返回 | 产品产生、母船完整收到、动作终止和成员释放分别记录。接收后触发至多一轮复查；返回从最后相关终态生成方法，不能无条件把滑行/trim终端叫作返回母船。 |

### 5.2 通信容量与母船知识的约束

固定0.1秒通信网格。对产品`p`，`b[p,v,k]`表示节点`v`在步首已持有的连续前缀；本步发送增量`d[p,u,v,k]`必须非负、链路/介质/视线有效，并满足

\[
d_{p,u,v,k}\leq\max(0,b_{p,u,k}-b_{p,v,k}),\qquad
\sum_{(p,u,v)\in c} d_{p,u,v,k}\leq C_c\Delta t.
\]

所有信道共用同一个步首快照；本步新收到的字节只能从下一步转发，防止函数调用顺序制造瞬时多跳。通知按编码字节数、摘要按32KiB共同消耗预算；同信道的**全部活动与全部产品**共享容量。产品仅在产生后传输，断链零增量，续传不重置前缀，重复通知/接收不能重复计数。声明模型仍是水下8m、2KiB/s与RF30m、32KiB/s，均为实验假设。

名义预测要用真实将派发的身份字段/时刻编码，或明确给出容量保守界；当前用候选名字和相对时间构造的名义通知不保证与在线编码等长。链路离散有效仅是声明的采样模型；没有连续可达/采样间运动界时不能升级为连续通信保证。

母船调度状态只能从已收到的状态、接纳、动作结果和产品构成；仿真传输与独立评测可读取真值，调度器不能据显示进度、bag或远端共享模型补齐失联信息。当前仅观测产品通过有限接收边界，Odometry、诊断与Action反馈仍有直接ROS通路；因此“产品有限交付”已实现，“全部决策均遵守有限通信知识边界”尚未实现。

上述模型是R1–R7机制结合本项目有限产品守恒与原生资格后的组合定义。数学符号仅用于解释现有字段的语义，不要求新增协议、任意目标权重或第二个求解器。

## 6. 编队的实际位置与必要纠正

当前Swarm承担AIR分布式轨迹优化，qn承担实际跟踪，二者都保留；没有理由再加一个编队控制器。USV/UUV协作是任务、通信和空间关系，不加入AAV编队图。

上层决定：在哪个任务段采用既有三机编队、何时集结、成员是否全部实际可用、何时解散。下层沿现有路径执行，继续记录原生相似度和实际净距；不把编队优化器放进高层每个时间步同步求解。

对同一作业段，独立运动候选与编队候选都必须包含完整代价：成员各自到集结位置、最慢成员等待、集结安全、编队转场、解散后续状态。当前把巡查后无条件追加编队动作的实现仅是回归演示，不是联合决策。

**不能假装编队天然提高监测效率或降低能耗。** R8说明多机器人收益必须有任务模型，R7提供编队运动方法及实验证据，不能据此推出本业务收益。若作业有明确同时观测/相对几何要求，编队是满足作业的候选方法；具体要求必须来自任务书/载荷合同。若没有这种需求或实测收益，优化器可能始终选独立动作，这是合理结果，不能用负代价、任意奖励或每次强制编队制造优势。

项目的编队能力验收可以在同一场景设一个明确标注的编队转场/收队工况，并与独立转场作对照；它是控制能力验收，不冒充未经证实的业务刚需。是否能在主业务任务中形成可发表的编队收益，是仍须验证的研究问题，不能由用户复选框替代，也不能从总交付中静默删除。

## 8. 理论与创新：把可以证明的结论和未证明的主张分开

研究问题仍是：**模式转换和交付可执行性如何改变异构任务分配与编队执行时序，并使执行反馈下的修复保持一致。** 下列是拟论证的条件性命题及证明路线，不是已经完成的统一稳定性/最优性定理。

- 事件/资源正确性：初始无冲突；每次派发在同一成员锁上原子检查/登记；只由匹配GoalID、代次与成功终端证据释放。可按状态转移归纳证明“不会双占、旧事件不释放新承诺”。接收因果可按通信步归纳：步首前缀限制保证本步不转发未来字节，容量预算保证同信道增量和不越界。这些是局部系统不变式，已有代码与定向反例支持，但尚未形成覆盖全部运行路径的机器验证证明，单独不称算法创新。
- 进展：需有有限活动集、联合事件先后无环、每个已接受动作/安全等待/终端有界、必要参与者持续可用、承诺通信窗口可达且累计容量足够，并假设就绪活动得到执行。此时可沿拓扑顺序归纳完成；缺少任一条件不能仅凭DAG无环推出进展。故障应正确失败/锁定，不承诺永久故障后仍成功。欠驱动平台没有合格等待过程时，APEX的节点等待论证不适用。
- 运动安全：若经过证明的连续时间位置跟踪界为e_i、e_j，球包络半径为r_i、r_j，则参考中心距至少为r_i+r_j+d_safe+e_i+e_j，才可由三角不等式推出实际机体净距至少为d_safe；当前经验误差不能直接当作这些界。Swarm软代价和PVS离散采样均不构成连续时间安全定理。
- 解质量：只对有限候选与声明模型讨论。完整枚举且所有可行性确定时，可取其最小`T_end`并与小规模穷尽参考对账；未知查询、未枚举的独立等待或缺少全计划约束时，即使当前`search_complete=True`也只说明当前搜索范围已结束，不代表§5的完整模型已解。预算未穷尽只能报告已找到的完整可行解；D-ITAGS的界不自动继承。
- 工程复用：请求/Plan/Action接线、原子锁、原生模型查询、Swarm软图项、有限字节账本和界面本身是必要系统实现，不单列为新理论。
- 可验证研究增量：在同一业务、物理与通信条件下，检验“完整模式方法+接收容量+承诺修复”是否改变平台/转换/支援/编队选择，以及是否改善实际成功率和完工时间。用串行/联合、忽略/计入转换、理想/有限交付、固定/反馈修复作消融；失败基线不得凭预测更快计成功。需记录方法集合、求解预算、实际收到的信息和最优性差距；仅工程接通或一个成功样例不足以证实创新。

## 9. 后续实施顺序及出口

1. **补全已加入的完整计划校核证据范围**：现有候选接受点已按绝对时刻检查所知成员运动和共享交付账本，碰撞/容量反例及水下正式runner实跑通过。继续提供AAV、已承诺前段、其他待命成员和规定返回的真实查询证据；缺失仍UNKNOWN，不以静止补齐，不新增通用框架。
2. **接通缺失的实际方法**：在同一10秒预算内完成AIR Swarm参考+qn完整方法查询，补有资格的AAV转换入口、独立/编队集结和解散、规定返回；未知不可用欧氏距离代替。保留时间/状态/七机回归未通过项，不放宽门槛。
3. **保持承诺的运行修复与信息边界**：用已接收状态重新查询未承诺部分，显式保留已接受未来会合。现有产品接收边界继续使用；控制/状态/结果也必须有声明可用的消息来源后才能宣称有限通信下的在线决策闭环。每增加一种实际消费者再增加其最少字段，不复制模型与历史。
4. **同一次确认完成请求**：在原worker上贯通空中/水下方法、支援、接收触发的一轮复查及规定返回；请求级通过由全部实际事件判定。五节点是代表验收配置，不强制每次使用全部平台；编队无收益可不选，但另有同场景原Swarm编队能力验收。
5. **少量有辨别力的对照**：复用同场景和声明模型评估第8节消融及小规模有限候选穷尽参考，不按函数数量补测试，也不扩论文/算法队列。

已有确定性边界不重复全面重测；后续只补会改变结论的反例：改变入口/支援可用时刻后选择变化、全计划共享容量不足、跨方法运动冲突、联合依赖成环、接收前不触发复查、未知/旧Result不解锁、预算耗尽仍保留承诺。最终安全、时间有效性、作业、接收和返回分别给出证据。
